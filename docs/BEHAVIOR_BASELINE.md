## 3. 测试矩阵（迁移后必须满足）

### 3.1 领域模型测试

| 用例 | 输入 | 期望 |
|---|---|---|
| 金额四舍五入 | `0.005`、`-0.001`、`NaN` | 统一为 `long` 分；NaN 拒绝 |
| 城镇余额 | deposit/withdraw 正负值、超额 | 不允许负数；超额失败 |
| 居民余额 | 同上 | 同上 |
| 国家余额 | 同上 | 同上 |
| 职位默认值 | 新居民、新城镇 | rank 为 null 或 RESIDENT |
| 城镇代码生成 | 中文名、重名、长度不足 | 唯一、3 位、冲突推位 |
| 国家代码生成 | 中文名、重名、长度不足 | 唯一、4 位、冲突推位 |

### 3.2 城镇服务测试

| 用例 | 场景 | 期望 |
|---|---|---|
| 建城 | 余额足够/不足/重名/非法名 | 成功扣费/失败无副作用 |
| 解散 | 有国库/无国库/有国家/无国家/有首都 | 资金、领地、居民、国家全部正确 |
| 合并 | 双方有国家/无国家/有首都 | 资金、领地、居民、首都、国王正确 |

## 5. 行为快照（MIG-004）

### 5.1 目的

在旧 Fabric 服务端录制关键场景的状态变化，迁移后用同一组输入重放，对比输出，作为"行为等价"的证据。

### 5.2 采集方式

1. 准备独立测试服（Fabric 1.21.8 + 本模组）。
2. 用命令脚本（RCON 或玩家指令序列）执行场景。
3. 每个场景结束执行 `/geo save`，采集：
   - `data/towns/*.json`
   - `data/nations/*.json`
   - `data/townblocks.json`
   - `residents` 表快照
   - 控制台日志（去除时间戳）
4. 归一化：排序 JSON 键、替换 UUID 为占位符、替换时间戳为相对值。
5. 输出到 `docs/snapshots/<scenario>.json`。

### 5.4 对照规则

| 差异类型 | 判定 |
|---|---|
| 金额差异 ≤ 0.01 | 允许（double→long 迁移） |
| 时间戳差异 | 归一化后忽略 |
| UUID 差异 | 占位符后忽略 |
| 列表顺序差异 | 排序后比较 |
| 其他差异 | 必须解释并记录到迁移报告 |

### 5.5 验收标准

1. 23 个场景全部产出基线快照。
2. 迁移后重放，差异项均有书面解释。
3. 金额、归属、rank、领地四类不允许出现未解释差异。

## 6. 新工程测试骨架

```
geotowny-plugin/
├─ src/main/java/
├─ src/test/java/
│  ├─ domain/          纯领域测试
│  ├─ service/         服务测试（内存仓储替身）
│  ├─ migration/       数据迁移测试
│  └─ snapshot/        行为快照重放
└─ build.gradle
```

`build.gradle` 测试依赖：

```groovy
testImplementation platform('org.junit:junit-bom:5.11.4')
testImplementation 'org.junit.jupiter:junit-jupiter'
testImplementation 'org.assertj:assertj-core:3.26.3'
testRuntimeOnly 'org.junit.platform:junit-platform-launcher'
```

平台集成测试优先使用真实测试服 + 脚本化冒烟；MockBukkit 仅作为可选补充，因 26.x 兼容性需实测。
